# Benchmark (yabs)

`assets/yabs.b64` is Yet Another Bench Script, **vendored verbatim** (WTFPL) and pinned by `YabsScript.upstreamCommit`/`sha256Hex`. Refresh with `scripts/update-yabs.sh`, which prints the three constants; the `vendored asset` group in `test/unit/benchmark/yabs_script_test.dart` fails until they match. `curl | bash` was rejected deliberately: it pins no version, verifies nothing, and `raw.githubusercontent.com` is unreachable from a large share of the hosts people benchmark.

- **No bundled asset may read as executable code, which is why that one is base64.** App Store validation walks everything inside `Runner.app` and treats a file it reads as code — a script suffix, or a leading `#!` — as a nested code object needing its own signature. Nothing under `flutter_assets` has one, so this costs nothing at build time and fails the *upload*: v1574 was rejected with `Invalid Signature. Code object is not signed at all.` naming `flutter_assets/assets/yabs.sh` and blaming the certificates. `YabsScript.decodeAsset` is the single decoder, shared with the test and matched by `openssl base64` in `update-yabs.sh`, and `sha256Hex` still covers the decoded script — the program a server is sent. The regression test walks every entry of pubspec's `assets:`, directories expanded, since the next asset to do this will not be this one.
- **The run is detached and the app only watches it.** yabs takes 10–20 minutes — longer than a phone holds a connection or the OS leaves a backgrounded app running. `YabsScript.startEntry` writes a generated launcher into the run directory and starts it under `setsid`, and `pollCommand` reads a directory. So closing the page, locking the phone or losing the network costs nothing, and reopening picks the run back up from the `benchmark_run` row (written at *start*, which is what makes that possible).
  - It also makes the transport irrelevant: every command is short, so this works over SSH **and** over a monitor agent's `/exec` with neither knowing about the other. That is why `ServerFuncBtn.benchmark` answers `caps.shell`.
  - The launcher records **its own** `$$`, not the shell's `$!`. Under `setsid` that pid is the process group every child inherits, and killing the group is the only thing that actually stops a benchmark — fio, iperf3 and Geekbench are separate processes.
  - `YabsPollState.answered` is load-bearing: a monitor agent that hit its own timeout answers with an empty body, and reading that as "the run directory is gone" fails a run that is going fine. Not answered means ask again; `dirExists` only means anything once `answered`.
- **`$HOME` cannot be single-quoted.** `YabsScript.quotePath` emits `"$HOME"'/rest'`; plain `quote` would send a literal `$HOME` and every command would operate on a directory of that name. Two values on these command lines are user-typed — the working directory and the custom iperf list — so `test/unit/benchmark/yabs_script_test.dart` runs the real fragments against `/bin/sh` and asserts an injected `; touch` does not execute.
- **Every phase is a user choice and the defaults are only defaults** (`YabsOptions`). Three disagree with yabs' own, each in the direction that spends less or discloses less: Geekbench off (it downloads a proprietary binary and **publishes** the machine's specs to a public `browser.geekbench.com` page), reduced iperf on (seven locations both ways is tens of GB of egress on a metered plan), IP lookup off (plaintext HTTP to ip-api.com). `BenchmarkEstimate` puts time, traffic and required free space above the Run button, because all three are invisible when the decision is made and expensive afterwards.
- **`YabsResult` parses leniently and the raw text is kept anyway.** yabs assembles its JSON with `+=` on a shell string, so a field it could not collect arrives as an empty slot and a distro name containing a quote produces a document no parser accepts. Nulls mean "not measured", never zero. `benchmark_run.result_json` holds the original so a later build can read what this one could not.
- `benchmark_run` is **not** a sync root — `conn_stat`'s reason, a measurement is not an edit — and is capped at `BenchmarkStore.historyLimit` per server, except that a `running` row is never pruned: it names a directory with a live process in it.
