# iOS / macOS native

- **CocoaPods is gone** — no `Podfile`, no `Pods/`, nothing named Pods in either `project.pbxproj`. `packages/fl_tty` builds its native code (pty, ish) with a build hook too. Do not add a pod back: the registry is read-only from 2026-12-02.
- **A privacy manifest is validated on upload and by nothing before it.** App Store Connect parses `PrivacyInfo.xcprivacy` strictly; `plutil -lint` (CoreFoundation, lenient) and `package:xml` both accept things it rejects. XML forbids `--` inside a comment, both those parsers allow it, and a comment added to `ios/Runner/` and `macos/Runner/` in `fa6043f3` carried it — the same prose in both, so both platforms were rejected together with `ITMS-91056: Invalid privacy manifest`, which names a path and nothing else. `xmllint --noout` is the one local tool that says so.
  - `test/unit/app/privacy_manifest_test.dart` covers every checked-in manifest: no `--` in a comment, plus keys, values and reason codes against **Xcode's own allowable-value list**, read out of `/Applications/Xcode.app/Contents/PlugIns/DVTCorePlistStructDefs.dvtplugin/Contents/Resources/DVTCorePlistStructDefs.xcplugindata` (`plutil -convert xml1`). That file is the authority for the ITMS-91054/91055/91056 family and pairs each API category with the reason codes valid *for it*.
  - Five manifests ship: `ios/Runner/`, `ios/LinuxFiles/`, `ios/StatusWidget/`, `ios/WatchApp/` and `macos/Runner/`. Another at `ios/PrivacyInfo.xcprivacy` was referenced by no target and reached no bundle, so it was deleted.
- The iOS Linux engine is linked into `fl_tty.framework` by fl_tty's hook. **On by default**; the hook runs `packages/fl_tty/scripts/ensure-ish-libs.sh`, which fetches the release built for the `packages/fl_tty/third_party/ish-arm64` gitlink into `packages/fl_tty/build/ish/` (outside `flutter clean`), or builds it locally when there is none (`brew install meson ninja llvm lld libarchive`). Off: `fl_tty: ish: false` under `hooks: user_defines:` in `pubspec.yaml`. Check a release build with `packages/fl_tty/scripts/check-ish-linkage.sh build/ios/iphoneos/Runner.app/Frameworks/fl_tty.framework/fl_tty on`. To test engine source edits, `packages/fl_tty/scripts/build-ish-ios.sh device` (or `simulator`): it stamps its output with the submodule HEAD, which keeps the hook from replacing it.
- **Debugging that engine needs SIGUSR1 passed through, configured outside this repo.** iSH interrupts guest threads with SIGUSR1 (signal delivery, task exit, every timer tick). LLDB stops on it, and `flutter run` installs a stop hook that prints every thread's backtrace and detaches — which in debug removes the `NOTIFY_DEBUGGER_ABOUT_RX_PAGES` breakpoint the Dart VM needs for an executable page, so the app dies. It gets reported as "Alpine crashes on launch", with the stop hook's own `bt all` attached. Put `process handle -n false -p true -s false SIGUSR1 SIGTTIN SIGPIPE` in `~/.lldbinit-lldb`: LLDB prefers `~/.lldbinit-<host program>` and ignores `~/.lldbinit` entirely when it exists, so this covers the lldb `flutter run` starts and leaves Xcode on the defaults. `pass=true` keeps the signal reaching the program.
  - Do not configure it through `Runner.xcscheme`'s `customLLDBInitFile`: on Xcode ≥ 26 `flutter run` starts a bare `xcrun lldb` and sets its breakpoint over stdin, so the scheme is never read. Tried in `bcc7b1a8`, reverted in `adab2745`.
- **`ios/LinuxFiles` is the Files app's view of the Linux systems** (#1855), a non-replicated `NSFileProviderExtension` serving `<App Group>/File Provider Storage/linux` in place (`FlTty.iosAppGroup`). Identifiers and link resolution follow Android's `LinuxDocumentsProvider`/`GuestPath`, but every change goes through `DirHandle` (`openat`/`*at`, `O_NOFOLLOW`): an iSH guest, unlike a proot one, cannot already reach outside its tree, so a directory swapped for a link must not take the extension there. `.installed` is never reachable. Each system's `/dev` database is in the app's own `Application Support/linux-dev`, never the App Group: a suspended app holding a lock in a shared container is killed (`0xdead10cc`), and a mounted fakefs holds one. Changes are not tracked: `enumerateChanges` answers `syncAnchorExpired`, so the Files app lists again. `ios/LinuxFiles/Tests/run.sh` runs `GuestPath`'s tests.
