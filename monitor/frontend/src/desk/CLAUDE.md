# The desk (the panel's web desktop)

The panel is a macOS-style desktop: a lock screen to choose a server, then that server's desk — menubar, dock, launchpad, windows, Spotlight, notification centre, desk icons. Everything the panel does is an app in a window. Agent side: `monitor/src/api/desk.rs` (`/desk*`, see `monitor/CLAUDE.md`).

## Layout

- `DeskRoot.svelte` — the login screen (`lock/LockScreen.svelte`: instances, each one's remembered accounts and sessions from `servers` — `signIn`/`useAccount`/`forget`, tokens per account in `sessionStorage`, names only in `localStorage` — and a clock styled per browser, `LockClock.svelte`) over one server's `Desk.svelte`, keyed by server id + token. Switching servers unmounts the desk (its agent keeps its windows); locking keeps it.
- `sys/` — **the app framework, the only way an app reaches the desk** (design and phases: `docs/dev/desk-sys.md`): `defineApp` (manifest), `registerApp`, `useWindow()` (state, title, app name/icon/badge, open, lifecycle), `useMenus()` (menubar menus; `shortcut`s run while the window is in front, `shortcuts.ts`), `useLifecycle()` (`active`/`visible`/`background`/`suspended`, `keepAlive`), `useDockMenu()`, `useIntents()` (+ `open(app, { intent })`, `handlers()` for "Open with"), `useWindow().notify()` and `.storage` (`appData.ts`), `AppToolbar`, `SplitView`, `WindowFooter`, `PageStack`. Every app has its page under Settings → Apps (`apps/settings/AppPage.svelte`, `{ section: 'apps', app }`): dock, running hidden, an installed app's permissions, and its manifest's `settings` page run as the app (`window/AppSettingsHost.svelte`). ESLint enforces it: an app imports `sys`, `lk` and code outside `desk/`, never the shell or another app (Settings alone may use `useDeskPrefs()`, `prefs.svelte`, `shell/Wallpaper`).
- `deskState.svelte.ts` — `Desk`: windows, prefs, notifications, each window's `WindowChrome` (`chromes`), lock/tab visibility, the shell's open panel/menu/Spotlight. `useDesk()` is for the shell only.
- `windows.svelte.ts` (state, no DOM) + `geometry.ts` (pure) — tested in `tests/deskWindows.test.ts`. `window/Window.svelte` is the chrome (pointer events: drag, 8 edges, snap to halves/top, double-click zoom).
- `session.svelte.ts` (window session, revision CAS, the focused tab wins), `prefs.svelte.ts` (per desk, on the agent), `shellPrefs.svelte.ts` (per browser: dock position/auto-hide/size, title bar glass or always; the window area keeps the dock's room), `notifications.svelte.ts`, `storage.ts` (`AgentStorage` when the agent lists `desk`, `BrowserStorage` otherwise), `deskApi.ts` (always to an explicit `ServerEntry`).
- The login screen shows each account's wallpaper from a copy this browser keeps (`lock/wallpapers.ts`, IndexedDB, written by `Desk.svelte` once its preferences load). Deliberately not an unauthenticated agent route: that would hand anyone who reaches the agent its accounts' names and images.
- `shell/` — Menubar (server + live dot, front app's name and menus (no icon), Window, Help; CPU reading, search, Control Centre, notifications, clock), Dock (left/bottom/right), Launchpad, ControlCenter, NotificationCenter, CalendarPanel, Spotlight, Banner, ContextMenu, DeskIcons, Wallpaper, AppIcon.
- `apps/<id>/` holds each app; **its `manifest.ts` (`defineApp`) is the app's only registration** (`apps/index.ts` finds them; `registry.svelte.ts` is the list the shell reads). Adding an app is adding its directory.
- `webapps/` — installed (`web`) apps: `register.ts` adds the agent's approved ones per desk, `WebAppFrame.svelte` runs one in a sandboxed iframe (opaque origin), `bridge.svelte.ts` answers its messages (protocol: `monitor/sdk/desk-sys/src/protocol.ts`, shared with the SDK) within its approved permissions; `backend.call` reaches a `wasm` app's backend. Settings → Apps installs/approves/removes (`InstalledApps.svelte`).
- `ui/` — TODO-remove shims. `lk/` — the design system (below).
- `desk.css` — window placement and animation, wallpaper light/dark; imports `lk/lk.css`.

## Design system: lollipopkit (`lk/`)

The desk follows the lollipopkit Design System exactly; `lk/` is its Svelte form. **Apps build their UI from `lk` and nothing else.**

- `lk/lk.css` — tokens (`--color-accent`, `--surface-*`, `--text-*`, `--border-hairline`, `--fill-hover`, `--space-*` odd scale 3/5/7/9/11/13/17/21/27/34/55, `--radius-*` 5/7/9/11/13/17/21/27, `--shadow-*`, `--glass-*`, `--dur-*`/`--ease-*` springs) scoped to `.lk`; dark via `data-theme="dark"` on <html> (`lib/theme.svelte.ts`). `lk-*` classes in `@layer components`. Values are the design system's; never invent one.
- Components (`lk/index.ts`): Icon (Material Symbols Rounded by name), Button (primary/secondary/tinted/ghost/destructive), IconButton, Badge, Input, Textarea, Select, Checkbox, Radio, Switch, Slider, SegmentedControl, Card (flat/raised/glass), Tooltip, Dialog, Notification, NotificationCenter, Menu, AppIcon, TrafficLights, SidebarSection, SidebarItem, ControlTile, Group + Row (SettingsGroup/SettingsRow), DataTable (sticky glass header, sort, solid-accent selection; a touch tap opens), StatTile, LegendChip, SearchField + ToolbarGroup (the title bar's pill controls), StatusBar, TitleTabs (tabs as the window title), Indicator, `viewIn`/`viewEnter` (`motion.ts`).
- Rules: one seed (berry `#730c37`, no accent picker); Figtree 13px body, JetBrains Mono for paths/permissions/terminal (`lk-mono`), tabular figures (`lk-num`); flat cards (no border, no shadow; `raised` only on a tinted ground); one hairline (`--border-hairline`, 0.5px); glass only for chrome over the wallpaper; selection in lists solid accent with white text, in sidebars soft accent with a filled glyph; segmented thumb raised white, never inverted; section headings `lk-caps`; sentence case, dry copy, no emoji; empty state = one 44–56px glyph + at most two words; press = shrink and spring back.
- **Tab motion, everywhere a view is one of N peers** (the design system's rule): one indicator glides between them (`--dur-indicator` · `--ease-indicator`): `SegmentedControl`'s thumb, `TitleTabs`, the login instance list (all through `lk/Indicator.svelte` but the segmented thumb). The incoming view fades in (`use:viewIn={key}`, `--dur-tab-content`), with no exit or slide; a new tab grows in (`--dur-tab-in`); a closed tab goes at once and the one left of it is shown. Sidebar navigation does not slide. Reduced motion shortens it (tokens).
- Icons: Material Symbols Rounded names only (no lucide in new code, no hand-drawn SVG). App icons: `AppIcon` glyph + tone from the app's manifest (an app may change them while it runs: `setIcon`).
- The window frame (`window/Window.svelte`) draws the title bar and the inset sidebar; an app puts its title/tools there with `sys.AppToolbar` and its sidebar with `sys.SplitView` (they register into `useWindow().chrome`). The 52px bar floats over the content, which scrolls under it (a spacer starts the body); it turns to glass once anything in the body scrolls, or always (per browser). A view that starts with a `DataTable` sets `flush` (solid bar; the table's header sticks under it). Lists are `DataTable`s with the selection's actions in `sys.WindowFooter` (a detail card over a `StatusBar`), as Processes, Services, Containers and Files do. `ui/SourceGroup`, `SourceItem`, `Segmented`, `Section`, `StatusPill` are TODO-remove shims; use `lk` instead.
- Never name where the design system was authored, in code or commits: it is "the lollipopkit Design System".

## Rules

- **A hidden window (minimised, desk locked, tab hidden) is not drawn but keeps running**; windows are keyed by id. With background running off (Settings → Apps) its content is unmounted after 5 s (`suspended`) and mounted again when shown, so an app restores itself from `appState`, saved as it changes. Work done only for the eye (polling a chart) stops while `useLifecycle().state` is `background`.
- **Wide windows** (the design system's rule): the sidebar never grows. A form or settings page is `pane-form` (640, centred), reading `pane-reading` (720), a dashboard or tile grid `pane-board` (1280); tables and lists fill. The gutter is `--content-pad` (21) at every width (`desk.css`).
- **Preferences, by where they live**: per browser — `lib/displayPrefs.svelte.ts` (clock 24/12, binary or decimal units; every time goes through `fmtDate`, every size through `fmtBytes`), `sys.systemPrefs` (refresh, density, text size, reduced motion, banners, start app, restore windows: apps read it), `shellPrefs.svelte.ts` (dock, title bar); per account on the server — `prefs.svelte.ts` (dock apps, wallpaper, background) and each app's own `storage` (its manifest's `settings` page, shown inline in Settings → Apps, edits it; the app reads the same keys, e.g. `apps/files/prefs.ts`).
- **A window body is a size container.** Apps use container variants (`@md:`, `@3xl:`), never viewport breakpoints (`sm:`, `md:`, `lg:`): a narrow window on a wide screen must lay out narrow.
- No `min-h-screen`, `h-screen`, `100vh`/`dvh` inside an app: the window is the screen. Use `h-full`/`min-h-full`.
- `position: fixed` inside an app is relative to its window (`.desk-window` has `contain: layout`, which makes it the containing block): a `Modal` is a sheet over its window, which is intended, and scrolls inside it when taller.
- An app never imports `layout`, `Sidebar`, `PageHeader` or `FeatureTabs` (being deleted). Its first element is `AppToolbar` from `sys` (no title at the app's first view — the window shows it; `title` + `back` for a view inside the app).
- **Tabs and split panes** (manifest `panes: true`; Terminal, Files): `window/PaneHost.svelte` runs the app's content once per pane, each with its own `useWindow()` (id = pane id, its own `appState`/title/chrome, `panes.newTab/split/close`); the window shows the focused pane's toolbar, sidebar, footer and menus. The layout is the window's `appState` (`panes.ts`, pure; a plain state is one pane keyed by the window id). All panes stay mounted in one flat list keyed by id (hidden tabs `visibility`+`inert`), so a split, a tab switch or a merge never remounts one. Dragging a window onto another of the app merges it (`Desk.mergeWindow`: over the bar or tab strip a tab, over a pane beside it on the nearest side) and the source goes by `windows.absorb`, not closed; a tab pulled off the strip becomes a window (`detachTab`). Key what outlives a mount by the pane id (Terminal's session handle); `closed` is true only for a pane or window really closed.
- Another window of the same app (`instances` > 1): `useWindow().openWindow(appState)`, offered as "New window" in the app's first menu and disabled by `canOpenWindow` at the limit (Terminal also has it in the bar; Files starts it at its folder).
- **Pages inside an app** (a list and what it opens, a folder and its folders) go through `sys.PageStack`: `key` names the page, `depth` how deep it is. Deeper arrives over (fl_lib's pane slide: in from the end edge, the page below a third out, `fastEaseInToSlowEaseOut` 300 ms); shallower is the same run backwards in time; as deep fades in. `back`/`forward` (`{ key, go }`) add a horizontal swipe (pointer, or a trackpad's two-finger swipe) unless what is under the pointer takes the drag (a field, a terminal, a canvas, `touch-action: none`, a box that can still scroll that way, text under a mouse; `data-no-page-swipe` opts out); the page swiped to shows as a still copy until the app is there. Never offer a swipe that ends something (Remote desktop's session). Status, Settings → Apps, Remote desktop and Files use it.
- Going to another app: `useWindow().open(appId, { appState })` for where it starts, `{ intent }` for something it should do once (never a shared module-level slot between apps). The receiving app reads `useWindow().appState` once on mount (and `$effect` on it if it should follow a second open, e.g. Files given a new path).
- Per-window state worth restoring after a reload (a path, a tab): `useWindow().setAppState(...)` — small JSON, ≤16 KiB, never secrets.
- Window title for a view inside the app: `useWindow().setTitle(...)`; `null` restores the app's name.
- Pages are per server: `servers.current` is this desk's server for the desk's whole life. The existing `stale(serverId)` guards stay.
- New shell text goes into `en` and `zh-CN` as `desk*` keys; the other locales are filled in one pass (every locale must have every key, `satisfies Translation`).
- `useDesk()`'s `menu`/`panel` are single: one context menu, one panel at a time; `Escape` closes them.

## Porting a page to an app (the recipe)

1. `git mv src/pages/X.svelte src/desk/apps/<id>/XApp.svelte` (replacing the temporary wrapper), and `git mv` the components only it uses into the same directory. Components used by several apps stay in `src/components/` and are not edited in a port.
2. Drop `Props { onback }`, `FeatureTabs`, `PageHeader`, `layout`. The page's header actions go into `AppToolbar`'s `actions`; a drill-down (detail view) gets `title` + `back`.
3. `layout.navigate('terminal')`-style jumps become `useWindow().open('terminal', …)`.
4. Breakpoints: `sm:` → `@2xl:`, `md:` → `@3xl:`, `lg:` → `@5xl:`, `xl:` → `@7xl:` (container sizes approximate the old viewport ones). Outer `max-w-* mx-auto px-4 sm:px-6 lg:px-8 py-8` becomes `mx-auto max-w-* px-4 py-4 @3xl:px-6`.
5. Its test (`src/tests/<x>.test.ts`) imports the new path and renders the app without `onback`; behaviour assertions stay.
6. Check: `npx svelte-check` (only locale gaps may remain), `npx eslint <files> --max-warnings 0`, `npx vitest run <its tests>`.
