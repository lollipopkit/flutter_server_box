为应对日益频发的黑客攻击与数据泄露事件，ServerBox 的自动同步（iCloud、WebDAV、LK Cloud）采用**双因素端到端加密**。解密云端同步数据必须同时具备你的**备份密码**和永不上传至服务器的 **128 位客户端安全密钥**。

> **注意：** ServerBox 无法看到你的数据，也无法找回丢失的安全密钥。若所有设备上的安全密钥均丢失，云端加密同步数据将无法解密，请妥善保存在密码管理器或离线介质中。

## 密钥层级

1. **备份密码**：由你在**备份**页面设定，用于保护本地 `.age` 导出文件并防止仅获取设备钥匙串后的离线访问；可随时修改，无需轮换安全密钥。
2. **安全密钥（`S1-...`）**：由操作系统 CSPRNG 生成 128 位随机熵，编码为 30 位 Crockford Base32 字符（`S1-XXXXX-XXXXX-XXXXX-XXXXX-XXXXX-XXXXX`），附带 22 位 BLAKE3 校验和。输入错误在密钥派生前即可在本地检出，且自动归一化易混字符（`I`/`L`→`1`，`O`→`0`）。
3. **派生口令**：
   ```text
   passphrase = BLAKE3_derive_key("lkc sync v1 secret-key passphrase", secret_key || len(password) || password)
   ```
4. **同步密钥封装（`identity.age`）**：X25519 同步密钥对保存在 `identity.age` 中，使用上述派生口令经 `age scrypt` 加密。
5. **数据封装**：同步备份、增量日志与快照均使用 X25519 公钥通过 `age` 加密；自动远程同步拒绝明文 JSON 与仅口令加密的数据。

## 完整性与防回滚（LK Cloud）

使用 LK Cloud 个人同步时，客户端还会使用 Ed25519 `AccountKey` 对写入进行签名认证：

- 文件、日志批次与快照在上传前均由客户端签名。
- 下载后先验证 Ed25519 签名再应用数据，拒绝未签名或伪造内容。
- 本地持久化单调递增版本水印，检测并拒绝被控服务端发起的回滚与重放攻击。

## 威胁模型

| 场景 | 系统行为 |
| --- | --- |
| 同步服务器或对象存储被攻破并拖库 | 攻击者仅能获取 `identity.age` 与 X25519 密文；缺少 128 位安全密钥时，无法对备份密码实施离线暴力破解。 |
| 被控服务器注入明文或单因素备份 | 自动远程同步拒绝明文及纯密码备份；完成双因素升级后，本地升级标记永久阻止降级回纯密码封装。 |
| 被控 LK Cloud 服务端伪造写入或回滚版本 | 客户端拒绝无效或缺失的 Ed25519 签名，以及低于本地水印的版本回退。 |
| 所有设备均丢失安全密钥 | ServerBox 与同步后端均不保存密钥副本，原有云端加密同步数据无法解密或找回。 |

## 存量设备升级

- **首台升级设备（设备 A）**：沿用原有备份密码，在你确认保存生成的安全密钥后，自动将 `identity.age` 原位升级为双因素封装。
- **其余 Apple 设备**：登录同一 Apple 账号时通过 iCloud 钥匙串自动同步安全密钥，无需手动输入。
- **其余 Android / Windows / Linux 设备**：通过扫码或手动输入 `S1-...` 字符串导入安全密钥；导入前仅暂停同步，不影响本地 SSH 连接。
