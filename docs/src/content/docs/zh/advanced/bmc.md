---
title: BMC(Redfish)
description: 在主机不响应时通过带外管理控制器访问服务器
---

BMC 是服务器主板上的一台小计算机，有自己的供电和自己的网口。主机关机、卡死、甚至
根本没装操作系统时它照样响应——这正是 SSH 和 monitor agent 做不到的事。

ServerBox 通过 **Redfish** 和它通信，也就是 2016 年前后至今大部分企业硬件提供的
HTTPS API。只支持 IPMI 的老机器不在支持范围内，原因见[工作原理](/zh/principles/bmc/)。

## 它能给你什么

- **服务器不可达时的电源状态。** `Power: on` 表示机器在跑、问题在别处；`Power: off`
  表示机器是关的。这是两个不同的问题，而服务器卡片本来分不出来。
- **硬件传感器**——进风口和 CPU 温度、风扇转速、整机功耗——读自 BMC 而不是操作系统内部。
- **电源控制**：给关着的机器开机，以及对不响应的机器执行关机、重启、电源循环、强制断电。

BMC 是 SSH **旁边**的一条通路，不是替代。一台服务器可以两者都有，通常也确实都有。

## 配置

1. 打开服务器编辑页，找到 **BMC (Redfish)** 一节。
2. **地址**——BMC 自己的地址，不是主机的。形如 `https://10.0.0.9`。只使用协议、主机和
   端口，路径部分由规范固定。
3. **账户**——选一个，或新建。见下。
4. **证书**——点开，和 BMC 自己的 Web 界面上显示的对比，然后接受。

之后服务器详情页会出现 BMC 卡片，电源按钮里会多出硬件级操作。

## 账户是共享的

BMC 账户是独立记录，不是在每台服务器里各填一遍用户名密码。BMC 通常整机架一起开通、
共用一个账户，所以二十台机器共享一条记录——轮换密码是改一次，而不是二十次。

管理入口在**设置 → BMC 账户**。每一条会显示有多少台服务器在用，因为在这里修改会改变
所有这些服务器使用的账户。

删除账户不会删掉用它的服务器。那些服务器保留地址、失去账户，编辑页会说明这一点。

## 证书

BMC 一律使用自签证书，没有任何证书颁发机构为它背书。ServerBox 在这里**不提供**
"忽略证书"开关——一个握有电源控制权的管理接口，是最不该有这种开关的地方。

它采用的是这个 App 对 SSH host key 已经在用的方式：你看一次证书并接受它，此后只接受
这一张证书。

**接受之前，把指纹和 BMC 自己的 Web 界面对一遍。** 这一步才是这套机制的价值所在。

如果指纹后来变了，App 会拒绝连接并说明。BMC 重新生成证书或固件升级时会正常发生这种
情况——而中间人攻击看起来也是这样。接受新的之前先核实。

很多 BMC 出厂时带的证书早已过期。ServerBox 会提示但允许接受；拒绝它们等于拒绝这个
功能面向的大部分硬件。

## 电源操作

电源按钮把操作系统级和硬件级的操作放在一起。两者不是一回事：

| | 经过操作系统 | 效果 |
|---|---|---|
| 关机 | 是 | 请求操作系统关机，需要 OS 在运行 |
| 重启 | 是 | 请求操作系统重启 |
| 开机 | 否 | 唯一对已关闭的机器有效的操作 |
| 强制断电 | 否 | 直接切电。未保存的数据丢失，文件系统不会卸载 |
| 电源循环 | 否 | 断电再上电 |

**优雅操作是一个请求，不是一个结果。** ServerBox 发出之后会去看上报的电源状态，而不是
相信 HTTP 响应——有些固件接受了优雅关机并返回成功，而操作系统什么都没做。等待时间内
状态没有变化时，App 报告的是"已接受"而不是"已确认"，字面意思。

服务实际允许哪些操作因厂商而异，ServerBox 是去问而不是假定：这台机器没有对应实现的
操作根本不会出现，而不是出现之后按下去失败。

## 尚未提供

事件日志、存储清单、启动项覆盖、虚拟介质都没有实现。通过 monitor agent 中转访问 BMC
也没有——那正是位于隔离管理网络上的 BMC 所需要的，目前手机必须能直接路由到 BMC。

宿主机与虚拟机的从属关系没有建模。跑在同一台服务器上的若干虚拟机会全部指向那台服务器
的 BMC，此时在其中任何一台上执行电源操作会切掉全部，而读回的电源状态是宿主机的而不是
虚拟机的。请把 BMC 配置在宿主机上。
